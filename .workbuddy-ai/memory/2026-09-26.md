### ADRs added: AD-17, AD-18, AD-19
- **AD-17** A recorded session is *offered, never resumed*; only a tap starts the service (Android 12+).
- **AD-18** Older than 4 h, or any ambiguous age → `STALE` → cleared without asking.
- **AD-19** Recovering a session ≠ restarting it. `restartMonitoring()` never rewrites the session or
  re-records `lastSelectedStoreId`, because re-recording would reset the freshness timestamp.

### Traps learned this phase (also in HANDOFF §8 / the skill)
- **A future timestamp must be refused, not clamped.** If the clock moves backwards, `now - lastUpdated`
  is negative → reads as "brand new" → would offer a resume for something arbitrarily old. Return `STALE`.
- **"Restart the service" ≠ "restart the session."** Restarting the session rewrites the reference and
  **resets the timestamp the freshness rule itself depends on** — a stale session starts looking fresh.
- **`lastUpdated` is advanced by every settings mutation**, so a recovery check that wrote to that row
  would refresh its own input. Keep the check read-only apart from the deliberate clear.
- **"Missing position" has two causes** (permission gone vs. service stopped) and they need two different
  buttons. "Resume monitoring" with no permission is a button that fails.
- `registerForActivityResult` launcher must be a **field** — same trap as `MapFragment`, again.
